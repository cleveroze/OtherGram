# OtherGram — масштабная разработка Telegram-форка

Ты — ведущий Android-разработчик проекта **OtherGram**.

Работай с GitHub-репозиторием `cleveroze/OtherGram`. Изучи существующий код, архитектуру, используемый Telegram API и систему настроек. Не переписывай весь проект без необходимости.

## Главная концепция

OtherGram — это альтернативный Telegram-клиент с огромными возможностями персонализации, но очень минималистичным, приятным и профессиональным интерфейсом.

**Главные приоритеты:**
1. Максимальная кастомизация приложения.
2. Кастомизация профилей, баннеров и бейджей.
3. Премиальный минималистичный дизайн.
4. Реально работающие функции, а не демонстрационные элементы.

## 3. OtherGram Profile Banners

Разработай полноценную систему баннеров профиля.

Баннер отображается в верхней части профиля пользователя.

Поддержка:
- PNG, JPG, WebP.
- Выбор изображения.
- Обрезка.
- Позиционирование.
- Удаление баннера.
- Цветной фон вместо изображения.
- Настройки отображения.
- Плавное появление.

Баннеры должны быть видны другим пользователям OtherGram, а не только владельцу.

Для этого спроектируй безопасную систему синхронизации метаданных и изображений через отдельный backend OtherGram, поскольку обычный Telegram API не предоставляет произвольные общие поля профиля для таких функций.

Используй стабильные Telegram user ID для привязки данных. Не публикуй приватные данные и не загружай личные изображения без согласия пользователя.

- Тонкая круглая обводка внутри.
- Белая галочка в центре.
- Аккуратный небольшой бейдж рядом с именем.

Типы бейджей:
- Developer.
- Administrator.
- Tester.
- Contributor.
- Project Friend.
- Early Supporter.
- Custom Badge.

У каждого бейджа могут быть собственные название, цвет и иконка.

Бейджи видны только пользователям OtherGram.

В официальном Telegram они не должны отображаться. Не выдавай их за официальную верификацию Telegram.

Добавь информационное окно, открывающееся при нажатии на бейдж, с названием и описанием.

## 5. OtherGram Admin Panel

Создай закрытую административную панель.

Администраторы проекта:
- `@milvet`
- `@velvet71`

Но права должны проверяться **по подтверждённым Telegram user ID на сервере**, а не только по username, поскольку username можно изменить.

Функции админ-панели:
- Выдача бейджей.
- Отзыв бейджей.
- Просмотр выданных бейджей.
- Создание новых типов бейджей.
- Настройка цветов.
- Настройка названий.
- Назначение нескольких бейджей.
- История административных действий.

Админ-панель не должна появляться у обычных пользователей.

Обязательно реализуй серверную проверку полномочий, чтобы обычный пользователь не мог выдать себе бейдж изменением локальных файлов или API-запросом.

Не добавляй секретные ключи и токены в публичный репозиторий.

## 6. Синхронизация между пользователями

Реализуй архитектуру, при которой пользователи OtherGram видят:
- Баннеры друг друга.
- Выданные бейджи.
- Дополнительные цвета имён.
- Публичные настройки оформления профиля.

Обычный Telegram не должен зависеть от этих функций.

Продумай backend, API, авторизацию, хранение изображений, кэширование, приватность и удаление пользовательских данных.

Если backend ещё не существует, сначала создай его основу и явно отдели реально работающие функции от тех, для которых пока требуется сервер.

## 8. Требования к разработке

Работай непосредственно с существующим Android-проектом.

1. Изучи репозиторий и зависимости.
2. Определи, какие функции уже существуют.
3. Составь архитектуру.
4. Раздели разработку на небольшие этапы.
5. Начни с нового меню OtherGram Settings, темы Vanilla Beige и системы кастомизации.
6. Затем реализуй локальную кастомизацию профиля.
7. После этого переходи к backend, баннерам, бейджам и админ-панели.
8. Создавай необходимые ресурсы, иконки и компоненты самостоятельно.
9. Проверяй компиляцию Android-проекта.
10. Исправляй найденные ошибки.
11. Делай осмысленные Git-коммиты.
12. Перед отправкой изменений на GitHub запрашивай подтверждение.

Не заявляй, что функция готова, если она не работает или не проверена.

Не создавай HTML-макет вместо Android-приложения.

**Начни с анализа репозитория, затем приступай к первому этапу разработки. Не пытайся реализовать все функции одним огромным непроверенным изменением.**
